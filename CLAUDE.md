# Помойка — Telegram-only агрегатор абсурдных новостей

Этот файл — постоянный контекст проекта. Ты (Claude Code) читаешь его в
начале каждой сессии в этом репозитории. Полная логика та же, что в
`docs/tz-codex.md` в этом же репозитории — сверяйся с ним по деталям, здесь —
только рабочие правила и краткая карта проекта.

## Что это

Конвейер: RSS-парсинг проверенных мировых СМИ → LLM-скоринг абсурдности +
safety-фильтр → перевод и рерайт на русском → рендер карточки → автопостинг в
Telegram-канал по расписанию. Без сайта, без фронтенда, без платежей.

## Технический стек (не менять без явного запроса владельца)

- Supabase (PostgreSQL), бесплатный tier
- Node.js
- GitHub Actions cron (30–60 минут)
- LLM API — модель в `.env` / GitHub Secrets, код не должен зависеть от
  конкретного провайдера (сейчас: OpenAI-совместимый эндпоинт, может быть
  OpenAI, DeepSeek или Claude API)
- Telegram Bot API для публикации
- Рендер карточки — HTML/CSS → PNG на том же раннере (`@vercel/og` или
  `node-canvas`), без внешнего платного API для изображений

## Структура репозитория (ожидаемая)

```
/db/schema.sql          — таблицы sources, news
/db/seed-sources.sql     — стартовый список источников
/prompts/editor.md       — промпт редактора (якоря оценки + примеры стиля,
                            заполняет владелец, не трогать структуру файла)
/scripts/parse.js        — RSS → сырые записи
/scripts/filter.js       — LLM-скоринг + рерайт
/scripts/post.js         — рендер карточки + публикация в Telegram
/.github/workflows/      — cron-конфигурация
/docs/tz-codex.md        — полное ТЗ с деталями по каждому требованию
```

## Правила работы в этом репозитории

1. **Один шаг за раз.** Роадмап ниже выполняется строго по порядку, один шаг
   на одну сессию/задачу. Не начинай следующий шаг, пока не показал, что тесты
   предыдущего прошли, и не получил подтверждение от владельца.
2. **Секреты никогда не в коде.** Все ключи и токены — только через `.env`
   локально и GitHub Secrets в проде. Если для шага нужен новый секрет —
   назови его переменной и сообщи владельцу, что нужно добавить, не проси
   значение напрямую в чате.
3. **`prompts/editor.md` — не код.** Не парсить его структурно, не навязывать
   ему формат кроме двух смысловых блоков. Это текст, который редактирует
   человек, а не конфиг, который генерирует Codex/Claude Code.
4. **Ошибки LLM не должны ронять пайплайн.** См. требование об
   отказоустойчивости в `docs/tz-codex.md` — необработанные записи должны
   переживать сбой и подхватываться следующим запуском.
5. **Не добавляй сайт, платежи, мультиязычность или другие источники
   (Reddit/Telegram-каналы) без явного запроса** — это осознанно исключено
   из скоупа, не забытая деталь.

## Роадмап

- Шаг 0 (не код, делает владелец): первая версия `prompts/editor.md`.
- Шаг 1: `db/schema.sql` + `db/seed-sources.sql` по списку источников из ТЗ,
  с проверкой актуальности каждого RSS-адреса перед записью.
- Шаг 2: `scripts/parse.js` — тест: прогон по всем источникам без падений,
  дубли по `original_url` отсекаются.
- Шаг 3: `scripts/filter.js` — тест: ручной прогон 200 записей, визуальная
  проверка соответствия оценок ожиданиям владельца.
- Шаг 4: `scripts/post.js` + workflow — тест: три автозапуска подряд без
  вмешательства человека, посты приходят в канал в правильном формате с
  карточкой.
- Шаг 5: `scripts/digest.js` + отдельный суточный workflow — дайджест дня
  (топ-5–7 по `absurdity_score` за сутки, ссылки на посты в самом канале,
  без вызова LLM). Тест: ручной запуск, дайджест приходит корректно.

## Как это запускать

Владелец открывает терминал в папке репозитория и пишет, например:
`claude "реализуй шаг 1 из CLAUDE.md"`. Дальше Claude Code сам читает этот
файл и `docs/tz-codex.md`, создаёт файлы, при необходимости — просит
подтверждение перед установкой новых зависимостей или созданием секретов.
